# Private Si I radiative-completion numerical validation

This directory prepares a numerical test of a private 35-level Si I atom with 250 radiative transitions and all 595 original bound CHIANTI collision rows. It does not change production data, fit cooling coefficients, or establish the physical accuracy of the NIST length-form E1 calculation. Source identity and radiative choices are documented in the [NIST audit](../si_i_electric_dipole_source_audit/README.md) and must be reviewed separately.

The candidate producer supplies `si_i_electric_dipole_source_audit/candidate_v2/candidate_result.json` containing `candidate_path`, `candidate_sha256`, `source_module_path`, `source_sha256`, `nlev`, `nrad`, `nups`, and `nodes`. Its source module must expose `source_atom()` returning the original Python `(levels, radiation, collisions)` records, independently of the written native atom. The validator does not infer or add `BT_TMIN_K`; it records the candidate's adopted numerical floor and uses its collision rows exactly as supplied. The expected 250 radiative rows are 229 existing CHIANTI pairs and 21 new NIST pairs. The existing pairs include 185 matched E1 transitions and 44 retained non-E1 rows; original E1, E2, M1, and M2 strengths can contribute to the 21 additional pairs, with multipoles sharing one pair summed into one rate. This count is a prospective check, not a completed profile result.

After the candidate producer and root reviewer approve the source model, run `make_plan.py` once to write a source-hashed `plan.json`. The eight controller steps are a 3-temperature pilot, compiled source-strength and 401-temperature population profiles at four densities, independent Python profiles, complete-profile PDF comparison, a stationary-state and energy-balance check, a numerical validation manifest, a conditional E1 length-versus-velocity sensitivity profile, and synchronous private atom/fit/registry products. The complete grid is 1,000–100,000 K with electron densities `1e-6`, `1e2`, `1e6`, and `1e10 cm^-3`. The controller uses one BLAS thread, an 8 GiB address-space limit, finite CPU and wall-clock limits, and preserves existing outputs. Launch it through a persistent tmux session only after root review; `launch_controller.sh` alone does not create a persistent session.

The compiled check uses the existing isolated `oxygen_valence_convergence/optimized_build/source_check.x` executable and freezes its executable, linked `nlevel_mod.o`, source files, raw atomic inputs, and candidate bytes. Passing numerical comparisons checks that the native implementation follows the selected source atom; it does not establish that the source rates are accurate at every temperature. The E1 gauge comparison measures sensitivity to the original calculation's two forms and is not an error interval. Automatic product preparation is conditional on all numerical gates; production activation still requires separate physical review of the complete plots and saved populations.
