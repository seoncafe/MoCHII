\begin{abstract}
How to build and run MoCHII (MOnte Carlo for H\,\textsc{ii} regions):
requirements, the complete input-parameter reference, output-file
formats, worked examples keyed to the regression tests, and the runbook
for adding an ion.  The physics and validation are documented separately
in \code{docs/MoCHII\_physics.pdf}; the atomic-data fitting code
in \code{docs/MoCHII\_fitting.pdf}.
\end{abstract}

\noindent\textbf{Current atomic-data scope (2026-10-11).}
Every metal element carries ionization stages I--VII (77 stages, 66
transitions); a band (\code{eion\_max}) above the ionization potential of
the stage-VII ion of an element present is refused (the lowest is
Cl\,\textsc{vii}, 114.2~eV, so the default 13.6--100~eV band runs).  Metal
photoabsorption is Verner's \code{phfit2} subshell sum, with the Nahar
(2019) R-matrix table for the Ne\,\textsc{iii} ground term.  The default
\code{metal\_excitation\_model = 'chianti'} takes the cooling fits, the
$n$-level atoms and the atomic-hydrogen collision files from
\code{data/atomic/excitation/chianti/}: full CHIANTI 11.0.2 atoms for 67
stages and Stout atoms for Cl\,\textsc{vii}, Ar\,\textsc{ii},
Ca\,\textsc{iv} (70 atoms, 6629 levels, 70 fits); \code{'mocassin\_v2'}
(55 atoms, 571 levels, 49 fits) is for parity runs.  Every stage with an
atom cools and emits.  The items removed on 2026-10-11 (\code{'extended'},
\code{additional\_line\_cooling}, \code{fe\_levels\_full},
\code{metal\_inner\_shell\_absorption}, \code{high\_charge\_exchange},
\code{pe\_scale}) are refused with their replacement named.  Benchmark
values quoted from runs before the restoration of 2026-10-11 (m11 or
earlier) are kept until the converged \code{m13\_restoration} runs replace
them; the record is
\code{md/ATOMIC\_PHYSICS\_RESTORATION\_RESULTS\_2026-10-11.md}.

\section{Requirements and build}
\begin{itemize}
\item Intel oneAPI MPI Fortran (the Makefile takes \code{mpiifort} when
  \code{ifort} is on the path, else \code{mpiifx}, else GNU \code{mpif90};
  \code{make F90=mpif90} forces one), HDF5 (default prefix
  \code{/data/opt/hdf5\_intel}; override with
  \code{make HDF5\_PREFIX=...}; \code{make HDF5=0} builds without it, FITS
  output only), CFITSIO.
\item The SEDust dust-emission library, self-contained under
  \code{SEDust/} in this tree.  Build it once with \code{cd SEDust/sed
  \&\& ./build\_lib.sh} ($\rightarrow$ \code{SEDust/sed/lib/libsedust.a}
  and its \code{.mod} files, which the Makefile links).  The SEDust
  \emph{data} directory is read at run time and resolved automatically
  relative to the executable (Section~\ref{sec:sedust}).
\item Python 3 with numpy/scipy (h5py, astropy, matplotlib, PyNeb for
  the test and fitting scripts).
\end{itemize}
Build:
\begin{verbatim}
   cd MoCHII
   (cd SEDust/sed && ./build_lib.sh)   # on a fresh checkout
   make -j16       # -> MoCHII.x   (clean + full rebuild, in parallel)
   make -j16 MoCHII.x   # rebuild only what an edit reaches
   make DEBUG=1    # bounds/traceback build
\end{verbatim}
The SEDust library only needs the one-time \code{build\_lib.sh} step;
afterward \code{make} links the in-tree SEDust library.
\code{make} alone cleans and rebuilds everything (the MoCafe default).
Module dependencies are tracked: \code{src/Makefile.dep}, written by
\code{tools/fortran\_module\_dependencies.py} from the \code{module},
\code{use} and \code{include} statements and regenerated whenever a source
changes, makes every object depend on the objects defining the modules it
uses and on the generated tables it includes (\code{src/*.inc}).  So
\code{make MoCHII.x} recompiles exactly what an edit reaches --- a new
component of \code{params\_type} in \code{define.f90} rebuilds every object
that sees \code{par} --- and \code{-j} orders itself.  (Before 2026-09-25 there
was no dependency tracking; an incremental build after such an edit linked
objects compiled against the old layout.)

Run:
\begin{verbatim}
   mpirun -np 8 ./MoCHII.x input.in
\end{verbatim}
MoCHII is MPI-only.  The octree, the opacities and the gas state live in
MPI-3 shared memory, one copy on each node, and so (since 2026-10-12) do
the arrays computed from the reduced transport tallies that every rank
would otherwise hold identically: the H, He and metal photoionization and
heating rates, the metal stage fractions behind the opacity, the He\,\textsc{i}
$2^3S$ rate $\Phi_3$, and the diffuse-field leaf tables; the ranks of a
node fill disjoint leaves of each.  The leaf emissivities of the metal
lines (\code{emis\_output}) are summed onto rank 0 in chunks, so only rank
0 holds that table.  What each rank keeps for
itself is what the photons deposit during a transport pass: the
energy-integrated path estimators of the photoionization and heating rates
(a few values per leaf and absorber) and, only with \code{jnu\_output} or
the SEDust emission, the $n_{\rm bin}\times n_{\rm leaf}$ band tally behind
\code{J\_nu} --- private, so the transport adds to them without locks, then
summed over all ranks.  The ionization and thermal solves of the leaves are then
divided over \emph{all} ranks of the job, cyclically by rank as the SEDust
solve is, and the solved leaves are summed back into every node's shared
copy (each leaf has one contributor, so the sum is exact), so adding nodes
divides the cell work too (since 2026-09-26; before, every node repeated
all leaves and the fixed-$T_e$ solve ran on one rank per node).  On several
nodes with Intel MPI, for example
\begin{verbatim}
   mpirun -hosts node1,node2 -ppn 36 -np 72 ./MoCHII.x input.in
\end{verbatim}
from a directory both nodes see: the outputs are written by rank 0 into
the working directory, under the base name of \code{out\_file} (its
directory part is dropped).

\section{Input parameters}
All input is one \code{\&parameters} namelist assigning fields of
\code{par}.  Parameters not listed keep the defaults shown.

\paragraph{Refused input.}  The input is checked before anything is built,
and a refused input ends the run with an \code{ERROR:} line from rank~0 and
exit status~1 on every rank, so \code{mpirun} returns~1 and a script can
test it.  Refused are: a missing or unreadable input file or one without a
\code{\&parameters} group; an unknown or misspelled item, or a value that
does not fit its item (the compiler's message is printed with the line it
names and the line before it, since Intel Fortran can name the line after
the offending one); a string item outside its set of values --- every such
item is checked whether or not the run reads it (\code{car\_walk},
\code{conv\_crit}, \code{file\_format}, \code{dust\_density\_law},
\code{amr\_type}, \code{ext\_geometry}, \code{slab\_faces},
\code{slab\_top\_mode}, \code{slab\_bot\_mode}, \code{src\_geometry}
in every slot, together with the items whose tables below list their
values); any of the MoCafe items of \S\ref{sec:mocafe_items}; an item
that was removed or renamed, with the replacement named
(\code{setup.f90::refuse\_removed\_items}: \code{metal\_inner\_shell\_absorption},
\code{additional\_line\_cooling}, \code{high\_charge\_exchange},
\code{fe\_levels\_full} and \code{pe\_scale} on 2026-10-11, \code{case\_ab},
\code{diffuse\_field} and \code{line\_case} on 2026-09-25), and
\code{metal\_excitation\_model = 'extended'}; a band (\code{eion\_max})
above the ionization potential of the last carried stage (VII) of an
element present (lowest: Cl\,\textsc{vii}, 114.2~eV); and the
combinations the tables below call refused.  A missing \code{amr\_file}
ends the run the same way (every rank reads it, so every rank reports).
The switches compose: \code{gas\_niter = 0} gives a single rates-only
pass; \code{gas\_niter > 0} iterates the ionization; \code{solve\_te}
(on by default) adds the thermal balance; \code{use\_metals} (on when the
input gives a metal abundance) the trace-metal registry;
\code{recombination\_continuum = 'transported'} (the default) the explicit
diffuse field (which also turns on the He\,\textsc{i} and He\,\textsc{ii}
excited-cascade channels \code{hei\_diffuse}, \code{heii\_diffuse} unless
the input sets them; \code{heii\_diffuse} set with \code{'on\_the\_spot'}
transports the He\,\textsc{iii} cascade alone);
\code{refine\_front} the I-front re-refinement; \code{ion\_add\_dust}
the dust coupling.

\subsection{Plane-parallel slab illumination}
\label{sec:slab}
With \code{source\_geometry\,=\,'slab'} (which requires \code{xy\_periodic},
\S\ref{sec:grid}) the box is an \emph{xy-periodic slab}: the medium varies in
$z$ (uniform in $x,y$ for a true 1D column with \code{nx\,=\,ny\,=\,1}, or an
arbitrary 3D tile with \code{nx,ny\,$>$\,1} repeated periodically), and light
enters through the top ($+z$) and/or bottom ($-z$) face.  Each face is either a
collimated \emph{beam} at incidence angle $\theta$ or an \emph{isotropic}
(Lambert) field, with its own strength.  The single physical normalization is
the flux $F_z$ crossing the (horizontal) illuminated face: for a beam
$F_z=\mu F_n$ ($\mu=\cos\theta$, $F_n$ the flux normal to the beam), for the
isotropic mode $F_z=\pi I$ ($I$ the specific intensity).  $F_z$ sets the packet
weight through $L=F_z\,A_{\rm zface}$; every result expressed per unit volume is independent
of the tile area.  Point-observer peel-off is refused under \code{xy\_periodic}
(setup stops if \code{ion\_peel} is set; the periodic images have no finite-distance observer); the emergent observable
is the boundary intensity $I(\mu)$ (\S\ref{sec:slabout}).

\subsection{Spectrum-file formats}
\label{sec:specfmt}
A single parameter, \code{spectrum\_type} (default \code{'shape\_ev'}), fixes
the column units of \emph{every} spectrum-file slot
(\code{ion\_spectrum}, \code{src\_spectrum\_file}, \code{ext\_spectrum}).
The type sets the units; the slot sets the meaning: an internal-source
file gives a luminosity density $L_X$, the external-field file gives an
intensity density $J_X$.  Column~1 and the value columns are:
\begin{center}\small
\begin{tabular}{llll}
\toprule
\code{spectrum\_type} & column 1 & internal (cols 2$+$) & external (col 2) \\
\midrule
\code{'shape\_ev'}   & $E$ [eV] $\uparrow$ & arbitrary per eV (shape of $L_E$) & arbitrary per eV \\
\code{'per\_ev'} & $E$ [eV]            & $L_E$ [erg\,s$^{-1}$\,eV$^{-1}$]      & $J_E$ \\
\code{'per\_hz'} & $\nu$ [Hz]          & $L_\nu$ [erg\,s$^{-1}$\,Hz$^{-1}$]    & $J_\nu$ \\
\code{'per\_ang'}& $\lambda$ [\AA]     & $L_\lambda$ [erg\,s$^{-1}$\,\AA$^{-1}$] & $J_\lambda$ \\
\code{'per\_um'} & $\lambda$ [$\mu$m]  & $L_\lambda$ [erg\,s$^{-1}$\,$\mu$m$^{-1}$] & $J_\lambda$ \\
\bottomrule
\end{tabular}
\end{center}
\noindent The external intensity density $J_X$ carries the same spectral
unit as the internal $L_X$ times an extra \,cm$^{-2}$\,sr$^{-1}$ (a mean
intensity).  All files are plain text with \code{'\#'} comment lines;
values outside the tabulated range are zero.  \code{src\_spectrum\_file}
is one multi-column file: column~1 shared by all sources, then one value
column for each source (extra columns beyond \code{nsource} are ignored
with a note, too few abort).

\medskip\noindent\textbf{The abscissa is a sample grid, not bin centers.}
Column~1 lists the points at which the spectral density is \emph{sampled}:
the file describes a continuous function, defined between the points by
linear interpolation (in $E$, after the unit conversion), and no bin widths
are attached to the rows.  Packet energies are drawn from that
piecewise-linear density itself, whose cumulative distribution is integrated
and inverted analytically, and the band luminosity is its integral; the
diagnostic band bins (\code{nnu\_ion}, \code{nnu\_fuv}) are filled
separately on a 32-point sub-grid of each bin (zero outside the tabulated
range), so the file grid and the band grid are independent and the bins
never enter the transport.  The spacing
is arbitrary --- nonuniform grids are fine; place points densely where the
spectrum varies rapidly, since only linear variation is captured between
adjacent points.  Abscissa values must be distinct (no duplicates); a
\code{'shape\_ev'} file must be ascending in $E$, while the physical types
accept any row order (the table is sorted internally after the unit
conversion, so a wavelength table may be given wavelength-ascending).

\medskip\noindent\textbf{Absolute vs.\ shape normalization.}  A physical
type (\code{'per\_ev'}/\code{'per\_hz'}/\code{'per\_ang'}/\code{'per\_um'}) is
\emph{absolute}: the source luminosity is the tabulated integral
itself.  If the matching scale (\code{luminosity} / \code{src\_lum}$(i)$
/ \code{ext\_intensity}) is unset it is DERIVED from the file --- each
internal source from its column's selected reference integral, the external field
from its band-integrated $J$ --- and reported in the log.  If a scale is
set, the spectrum is RESCALED to it and the file then acts only as a
shape, and a note gives the file's own value and the scale: for an
internal source, in either \code{luminosity\_reference} mode, its
reference integral; for the external field (a physical-type file or an
ISRF preset rescaled by \code{ext\_intensity}), its band-integrated $J$.  With \code{add\_fuv} an absolute spectrum fills the
FUV bins from the same table, with no separate normalization.
For a multi-column physical source file, set each \code{src\_lum} to
rescale its column; a common \code{luminosity} alone does not override
the independently derived column luminosities.
\code{'shape\_ev'} keeps the legacy behavior: the shape is normalized to the
scale in every case.  A spectrum with no luminosity inside the transported
band aborts, as does rescaling a file whose selected reference integral is zero.

\medskip\noindent\textbf{Full-spectrum reference for point sources.}
With \code{luminosity\_reference='full\_spectrum'}, the input
\code{luminosity} or \code{src\_lum} is the integral of $L_E$ over the
entire tabulated energy interval, or over $0<E<\infty$ for a Planck
spectrum.  File spectra are converted to $L_E$ first, then integrated
using the same piecewise-linear interpolation that samples packet
energies; nothing is extrapolated beyond the file endpoints.  An unset
scale for a physical-type internal file keeps its absolute luminosity.
The transported point-source power is the integral of the normalized
spectrum over [\code{efuv\_min}, \code{eion\_max}] with \code{add\_fuv},
or [\code{eion\_min}, \code{eion\_max}] otherwise.  Energy outside that
interval contributes to the reference luminosity but launches no packet.
The H-ionizing and FUV shares are determined by the selected spectrum;
changing the transport limits does not redefine the input scale.
\code{ext\_intensity} and slab source strengths retain their band
normalization, including in a mixed point-source and external-field run.

\medskip\noindent\textbf{\code{'shape\_ev'} is per eV, not variable-agnostic.}
\code{'shape\_ev'} reads its value columns as the shape of the density per eV
$L_E$ on the $E$~[eV] grid of column~1.  A table of $F_\lambda$ (or
$F_\nu$) values re-gridded onto $E$ under \code{'shape\_ev'} therefore omits the
Jacobian and is wrong by a factor $E^{-2}$ (the $\mathrm{d}\lambda/\mathrm{d}E$
conversion).  To use a wavelength- or frequency-tabulated shape, give it
with its matching physical type and set the scale explicitly --- the type
conversion then applies the Jacobian and the scale RESCALES the file to
your target, so the file acts as a shape with the correct units.  For
example, a wavelength shape normalized to $10^{49}$ ionizing photons'
worth of luminosity:
\begin{center}\small
\begin{verbatim}
par%spectrum_type = 'per_ang'
par%ion_spectrum  = 'wave_shape.txt'
par%luminosity    = 3.0e38
\end{verbatim}
\end{center}

\medskip\noindent A small \code{'per\_ang'} source file for two point
sources ($\lambda$ ascending; the second source is FUV-faint):
\begin{center}\small
\begin{verbatim}
# lambda[A]   L_lam,1        L_lam,2
   300.0      7.80e34        3.4e33
   500.0      6.05e34        1.2e33
   912.0      4.10e34        0.0
\end{verbatim}
\end{center}

\subsection{Convergence of the gas iteration}
\label{sec:convergence}
The gas iteration (\code{gas\_niter} sweeps of transport $\rightarrow$ rate
integrals $\rightarrow$ leaf solve $\rightarrow$ opacity refill) stops when
the state stops changing between sweeps.  Each sweep compares a \emph{change
measure} against a tolerance:
\begin{itemize}\itemsep2pt
\item ionization only (\code{te\_fixed}, no thermal solve): converged when the
  $x_{\rm HII}$ change $<$ \code{gas\_tol};
\item coupled (\code{solve\_te}): converged when the $x_{\rm HII}$ change $<$
  \code{gas\_tol} \emph{and} the $T_e$ change $<$ \code{gas\_tol\_te}.
\end{itemize}

\paragraph{Two measures (\code{conv\_crit}).}  Both are computed every sweep;
\code{conv\_crit} selects which one gates the loop.
\begin{description}\itemsep2pt
\item[\code{'cell'}] the cell maxima $\max_{\rm leaf}|\Delta x_{\rm HII}|$ and
  $\max_{\rm leaf}|\Delta T_e|/T_e$.  Simple, but the ionization-front cells
  jitter with Monte Carlo noise and never settle, so $\max|\Delta x_{\rm HII}|$
  \emph{stalls} at the front-cell noise floor ($\sim$2--4$\times10^{-2}$ at
  $4\times10^7$ packets) and a smaller \code{gas\_tol} is unreachable.  This is
  the historical default (kept so the recorded gates reproduce).
\item[\code{'vol'}] the volume-integrated $L_1$ changes
  \[
    d_x = \frac{\sum_{\rm leaf} V\,|\Delta x_{\rm HII}|}{\sum_{\rm leaf} V\,x_{\rm HII}},
    \quad
    d_{\rm He} = \frac{\sum_{\rm leaf} V\,|\Delta x_{\rm HeI}|}{\sum_{\rm leaf} V\,(1-x_{\rm HeI})},
    \quad
    \frac{\sum_{\rm leaf} V\,n_e\,|\Delta T_e|}{\sum_{\rm leaf} V\,n_e\,T_e}
    < \code{gas\_tol\_te},
  \]
  with the He$^+\to$He$^{2+}$ measure added where He$^{2+}$ is at least 1\%
  of the ionized helium.  The ionization measures are tested on the
  \emph{drift still to come}, not on the last step: with $\rho$ the decay
  ratio fitted to $\ln d$ over the last 8 iterations, a measure passes when
  $d\,\rho/(1-\rho) <$ \code{gas\_tol}, or, once it has stopped decaying
  ($\rho \ge 0.95$), when $d <$ \code{gas\_tol} \emph{and} the signed
  change of the ionized volume, $s = \sum V\,\Delta x_{\rm HII}/\sum V
  x_{\rm HII}$ (and its helium counterparts), has no mean over those 8
  iterations that stands out of its scatter (Student's $t < 2.365$;
  with \code{conv\_drift\_test = T}; the default F, since 2026-10-18, drops this condition).  That
  second condition is what tells the Monte Carlo floor, where the leaves
  fluctuate about their fixed point and their changes cancel in $s$, from a
  front still moving slowly, which changes the ionized volume with one sign
  every iteration.  No measure passes before 8 iterations, restarts
  included.  A test on the step
  alone stops too early when $\rho$ is close to 1: on the HII40 benchmark
  ($\rho \approx 0.86$) it stopped at iteration 37 with the He\,\textsc{i}
  front 0.17~pc short of where it settles.  Of the 80-iteration run that
  showed this (2026-09-25), the drift test of that day stopped at 58, at the
  80-iteration answer; the window test described here has not been replayed
  on it, since that run's log carries no signed change $s$.  Reading the floor off the step alone was not
  enough either: a restart whose front was still moving slowly
  ($\rho \approx 0.97$) passed after 4 iterations because one noisy step
  ratio reached 1.  Each iteration prints $d$, $\rho$, the drift, the mean
  signed step $s$ and its $t$ for $x_{\rm HII}$ and helium
  (\code{fixed point} lines).
  Front jitter occupies little volume (a few thousand front cells against
  $\sim$$10^5$ ionized ones), so it enters the norm suppressed by that ratio;
  the $n_e$ weight drops the vacuum and \code{te\_min}-pinned no-heating cells
  that otherwise dominate $\max|\Delta T_e|$ in FUV/PDR runs.  These measures
  decay smoothly --- the recommended production setting.
\end{description}

\paragraph{The Monte Carlo floor.}  Even the volume measures do not reach
zero: they floor at a Monte Carlo level set by the packet count, scaling as
$1/\sqrt{N_{\rm packets}}$ ($\sim$3$\times10^{-3}$ in $x$ and
$\sim$7$\times10^{-3}$ in $T_e$ at $8\times10^6$ packets, measured on the
FUV dusty Str\"omgren case).  Reaching the floor
\emph{is} convergence --- iterating further leaves the solution unchanged.  So
\textbf{set \code{gas\_tol}/\code{gas\_tol\_te} just above the floor for the
packet count in use}: a tolerance below the floor can never be met and the
loop runs to \code{gas\_niter} and warns.  Rules of thumb
(\code{conv\_crit='vol'}): $\sim$$5\times10^{-3}/10^{-2}$ at $\sim$$10^7$
packets, loosened to $\sim$$10^{-2}/2\times10^{-2}$ at $\sim$$10^6$ (the
reduced-count \code{examples/} use the looser values for this reason).

\paragraph{When it does not converge.}  Hitting \code{gas\_niter} without
meeting the test is not fatal: the state is still written and a warning is
printed on rank~0.  Set \code{require\_convergence = T} to abort before the
output instead.  Either way the \code{\_rates} header records the outcome in
\code{CONVERGD} (0/1), \code{NITERDON} (sweeps run), \code{FINALDX}, and
\code{FINALDTE}.  The derivation and the gate measurements are in
\code{docs/MoCHII\_physics.pdf}.

\subsection{Reading outputs in Python}
\code{tools/python/mochii\_output.py} is an importable module (works
directly in a notebook) that reads every section file (HDF5 or FITS;
\code{read\_sections}), the line table (\code{read\_lines\_table}),
and the text spectra (\code{read\_spectrum}), and builds 2D maps from
the emissivity file:
\begin{verbatim}
import sys; sys.path.insert(0, ".../MoCHII/tools/python")
import matplotlib.pyplot as plt
from mochii_output import EmisData

d = EmisData("run_emis.h5")
d.info()                            # blocks, fields, line count
d.line_list()                       # every stored line (block, wl)

# ready-made figures (notebook): returns (fig, ax)
fig, ax = d.plot_line("o_3", 5007.)                  # log S map
fig, ax = d.plot_line("h", 6563., unit="intensity",
                      photons=True)  # photons/s/cm^2/sr
fig, ax = d.plot_field("T_e", weight="EM")
fig, axs = plt.subplots(1, 2); d.plot_line("s_2", 6717., ax=axs[0]) \
    ; d.plot_line("s_2", 6731., ax=axs[1])   # doublet side by side

# raw arrays, when the figure is yours to build
img, ext = d.line_map("o_3", 5007., axis="z", npix=512)
img, ext = d.line_map("h", 6563., unit="intensity", photons=True)
img, ext = d.field_map("T_e", weight="EM")   # LOS-weighted average
Q = d.line_luminosity("h", 4861., photons=True)  # photon rate [1/s]
\end{verbatim}
Line maps are flux-conserving: each leaf's luminosity is deposited
with exact area overlap onto the pixel grid (AMR leaf sizes handled),
so $\sum S\,A_{\rm pix} = L_{\rm line}$ to machine precision.
\code{unit='flux'} (default) gives surface brightness
[erg\,s$^{-1}$\,cm$^{-2}$]; \code{unit='intensity'} gives specific
intensity [erg\,s$^{-1}$\,cm$^{-2}$\,sr$^{-1}$] $= S/4\pi$ (isotropic
emission, optically thin); \code{photons=True} converts either to
photon units (divides by $hc/\lambda$ of the line).  A
\code{slab=(lo,hi)} cut restricts the line of sight.  Field maps
average \code{T\_e}, \code{n\_e}, \code{x\_HI}, \dots\ along the line
of sight with weight \code{'EM'} ($n_e^2 V$), \code{'ne'},
\code{'nH'}, or \code{'V'}.  The same module doubles as a
command-line tool for quick looks:
\begin{verbatim}
python3 mochii_output.py run_emis.h5                  # list lines
python3 mochii_output.py run_emis.h5 --line o_3 5007 \
        --npix 512 --log --out o3.png
python3 mochii_output.py run_emis.h5 --line h 6563 \
        --unit intensity --photons     # photons/s/cm^2/sr
python3 mochii_output.py run_emis.h5 --field T_e --weight EM
\end{verbatim}

\subsection{Slices and cutouts}
A \emph{slice} is the actual leaf value on a plane (the cell that contains
each pixel), distinct from the line-of-sight \emph{projection} above --- a
slice resolves the ionization front sharply where a projection blurs it.
\code{tools/python/leaf\_field.py} holds the backend
(\code{leaf\_slice}, the nearest-leaf fallback \code{leaf\_slice\_nn}, and
\code{plot\_slice}); \code{mochii\_output.py} exposes it on the output
files:
\begin{verbatim}
from mochii_output import EmisData, RatesData
r = RatesData("run_rates.h5")                 # leaf state
fig, ax = r.plot_field_slice("T_e", axis="z", coord=0.0)
fig, ax = r.plot_field_slice("x_HI", axis="z", coord=0.0, log=True)
img, ext = r.slice_field("n_e", axis="x", coord=0.0,
                         bounds=(-2,2,-2,2))  # cutout window

d = EmisData("run_emis.h5")
fig, ax = d.plot_line_slice("o_3", 5007., axis="z")   # emissivity slice
\end{verbatim}
Exact slices need the leaf full widths: the \code{\_emis.h5} file always
carries \code{LeafSize}, and \code{\_rates.h5} does too; a rates file
written before \code{LeafSize} existed falls back to a nearest-leaf
slice (a one-time note is printed).  The command line takes
\code{--slice FIELD --axis z --coord 0} on either file.

\subsection{He\,\textsc{i} 2$^3$S metastable and 10833~\AA\ absorption}
The \code{\_heimeta} file (\code{hei\_metastable}) is read by the
\code{HeiMetaData} class, which adds a line-of-sight column map and the
10833~\AA\ line-center optical depth:
\begin{verbatim}
from mochii_output import HeiMetaData
d = HeiMetaData("run_heimeta.h5")
d.info()                                   # n_2s3, Phi_3, line constants
img, ext = d.column_map("n_2s3")           # LOS column [cm^-2]
img, ext = d.tau10833_map(v_turb=0.0,      # tau_0 map (km/s turbulence)
                          component="doublet")  # blended J'=1,2 pair
fig, ax = d.plot_column("n_2s3", log=True)
fig, ax = d.plot_tau10833(component="all")
\end{verbatim}
\code{column\_map} is the same flux-conserving deposit as the line maps
with weight $n\,V$, so $\sum N\,A_{\rm pix} = \sum n\,V$ to machine
precision.  \code{tau10833\_map} deposits the line-center opacity
$\kappa_0 = \frac{\sqrt{\pi}\,e^2}{m_e c} f\,\frac{\lambda}{b}\,n_3$,
$b = \sqrt{2 k T_e/m_{\rm He} + v_{\rm turb}^2}$, so a pixel value is
$\int\!\kappa_0\,{\rm d}l$.  \code{component} selects the resolved
$J'=0$ line (10832.06~\AA), the blended $J'=1,2$ \code{'doublet'}
(10833.22/10833.31~\AA, 0.089~\AA\ apart, inside the thermal Doppler
width), or \code{'all'}; the constants ($\lambda$, $f$, $A$) come from
\code{data/atomic/hei\_metastable.txt}.  The map warns when line-center
$\tau_0 > 1$: the diagnostic assumes optically thin 10833 (line transfer
is out of scope).  The command line takes \code{--column n\_2s3} or
\code{--tau10833 --component doublet --vturb 5}.

Where line transfer \emph{is} wanted (resonant-scattering emission
profiles from the metastable medium), \code{heimeta\_to\_lart.py} (in
\code{tools/python/}) converts a \code{\_heimeta} file into a
scattering-medium input for the resonance-line code LaRT (line
\code{HeI\_10833}): \code{--format car}
(default, uniform grids) writes the all-in-one Cartesian file with
\code{gasDen} $= n_3$, \code{T} $= T_e$, and zero velocities;
\code{--format amr} writes the generic AMR table with $n_3$ in the
\code{n\_ion} column.  \code{--field} selects a different leaf field for
the scatterer.  A worked end-to-end case (converted grid + LaRT namelist)
is in \code{examples/hei\_metastable/lart/}.

\subsection{Building AMR grids}
\code{tools/python/AMR\_grid/} builds the generic AMR octree file the code
reads (\code{grid\_type='amr'}): \code{AMR\_grid.py} (the \code{AMRGrid}
class --- uniform, density-gradient, or resolution refinement;
\code{set\_density}/\code{set\_neutral\_fraction}; \code{write} to
HDF5/FITS/\code{.fits.gz}/text with columns \code{x,y,z,level,nH}
[\code{,metallicity,xHI,ndust}]) and \code{make\_amr\_sphere.py} (a
sphere/shell CLI).  \code{AMRGrid} carries the same
\code{slice}/\code{plot\_slice}/\code{cutout} so a grid can be inspected
before a run.

\section{Adding an ion}
Adding an ion touches only data:
\begin{enumerate}
\item The atom and its cooling fit: for the \code{'chianti'} model the
  full CHIANTI atom is written by
  \code{tools/fitting/\allowbreak chianti\_cooling.py} (every bound
  collision-connected level and every row) and its low-density cooling
  fitted by \code{tools/fitting/\allowbreak fit\_cooling.py}, into
  \code{data/atomic/\allowbreak excitation/\allowbreak chianti/} with the
  \code{manifest.json} updated
  (\code{tools/fitting/\allowbreak chianti\_excitation\_model\_coverage.py};
  checks \code{validate\_chianti\_\allowbreak excitation\_model.py};
  \code{md/atomic\_stage\_expansion/\allowbreak chianti\_model\_2026-10-11/}).  Check
  the reported maximum fit error.  \code{fit\_nlevel.py} writes the older
  Chebyshev form, which the reader still accepts.
\item \code{tools/fitting/make\_element\_data.py}: add the element to
  \code{ELEMENTS} (Z, stage count) and its thresholds; charge exchange
  entries where sources exist; run.  The CHIANTI
  \code{.rrparams}/\code{.drparams} types 1--3 are handled
  (\code{RR}/\code{RR2}/\code{DR}/\code{DR2} lines).  The photoionization
  rows are parsed from Verner's \code{phfit2.f} itself and follow its
  prescription: \code{PHOTO} $E_{\rm th}\,E_0\,\sigma_0\,y_a\,P\,y_w\,y_0\,y_1$
  (the VFKY96 outer-shell fit, used below the first inner-shell edge; written
  when that edge is above zero), \code{PHINNER} $E_{\rm inn}$ (\code{phfit2}'s
  \code{einn}; 0 for the elements absent from the VFKY96 table, e.g.\ Cl,
  which then use the subshell sum at every energy), and one \code{PHSHELL}
  $l\,E_{\rm th}\,E_0\,\sigma_0\,y_a\,P\,y_w$ row for each occupied subshell
  (Verner \& Yakovlev 1995), summed at and above $E_{\rm inn}$.  The reader
  refuses a transition with no \code{PHSHELL} rows, or with
  $E_{\rm inn} > 0$ and no \code{PHOTO} row.  A \code{PHTABLE} $n$ record followed by $n$
  rows $\epsilon\;\sigma$ (photoelectron energy $\epsilon = E - E_{\rm th}$
  [eV], cross section [Mb], linear in $\epsilon$) replaces \code{PHOTO}
  below its last node, where it must end on the \code{PHOTO} fit; only
  Ne\,\textsc{iii} carries one (Nahar 2019 R-matrix, written by
  \code{tools/fitting/ground\_term\_photoionization\_table.py}), and the
  reader refuses a table that is short, not increasing from $\epsilon = 0$,
  negative, reaches $E_{\rm inn}$ or does not join the fit.  A charge-exchange rate given
  as a table is \code{CXR 8} followed by
  \code{CXRTAB} $n\;T_1..T_n\;k_1..k_n$ ($n \le 1024$; K and cm$^3$\,s$^{-1}$,
  interpolated log--log, $T$ held at the table ends), as for the Barragan
  et al.\ (2006) N$^{2+}$ and O$^{2+}$ rows.  A transition resolved by the
  product term of the ion is \code{CXI 9} and \code{CXR 9} followed by
  \code{CXSTATE} $n_{\rm term}\;n_T\;g_{\rm react}\;\Delta{\rm IP}$,
  \code{CXSTATET} $T_1..T_{n_T}$ and one \code{CXSTATEK}
  $label\;l_{\rm lo}\;l_{\rm hi}\;g\;E\;k_1..k_{n_T}$ row for each term
  (its levels in \code{nlevel\_<el>\_<stage+1>.txt}, weight, energy [eV],
  forward rate into it): the forward rate is the sum, the reverse each
  channel's detailed balance weighted by the term's population from that
  $n$-level atom at the local $(T, n_e)$ (sulfur, Zhao et al.\ 2005).
\item Atomic-hydrogen impact (optional, for a neutral-gas coolant): a
  \code{hcoll\_<el>\_<stage>.txt} beside the $n$-level file in
  \code{data/atomic/excitation/<model>/},
  written by \code{tools/fitting/make\_hcoll\_fine\_structure.py}: a
  \code{NHCOL} $n$ line, then $n$ rows
  \code{lo hi form Tmin Tmax c\_1..c\_10} with the level indices of the
  $n$-level file; form~1 is the Abrahamsson et al.\ (2007) Eq.~1 excitation
  fit ($c_1 = b$, $c_{2\ldots} = a_i$), form~2 a de-excitation power law
  $c_1 (T/100)^{c_2}$.  It is picked up automatically and used under
  \code{neutral\_hydrogen\_excitation} (default on).
\item Fortran (only for a NEW element; new stages of a known element need
  nothing): a \code{par\%abund\_<El>} component of \code{params\_type} in
  \code{define.f90}, one entry in the name/abundance lists of
  \code{species\_mod::species\_setup}, and one in the abundance list of
  \code{setup.f90::read\_parameters\_with\_implicit\_defaults} (\code{NAB},
  \code{ABNAME}, \code{set\_abundances}, \code{abundances}), which decides
  \code{use\_metals} from the abundances an input gives.
\item Verify: extend \code{verify\_nlevel\_pyneb.py} with a diagnostic
  ratio where PyNeb has data; run a smoke test and check the new lines
  in \code{\_lines.txt}.
\end{enumerate}
Data caveats met so far: Ar\,\textsc{ii}, Ca\,\textsc{iv} and
Cl\,\textsc{vii} have no CHIANTI 11 valence collision data (Stout atoms are
used); Ar\,\textsc{i}, Cl\,\textsc{i}, Ca\,\textsc{i}, Fe\,\textsc{i},
Cl\,\textsc{v} and Ca\,\textsc{iii} have no atom (stages tracked without
lines); Fe\,\textsc{iii}
collision strengths differ from PyNeb's BB14 by up to $\sim$16\% in
4658/4702 (known spread for iron); charge-exchange stage labels differ
between the Huang (2023) and MOCASSIN transcriptions for Mg/Fe (the
Huang labels are adopted; see \code{make\_element\_data.py}).

\section{Practical notes}
\begin{itemize}
\item \textbf{Bins}: the photoionization and heating rates come from
  path estimators at the exact packet energies, so the bin count
  (\code{nnu\_ion}, \code{nnu\_fuv}) sets only the resolution of the
  diagnostic spectra (\code{J\_nu}, the peel-off cubes, the SEDust leaf
  spectrum), never the solution.  The \code{add\_fuv} extension carries its
  own bins below \code{eion\_min}.
\item \textbf{FUV and the PDR}: without \code{add\_fuv} there is no
  radiation beyond the I-front and the metals there recombine toward
  neutral; with it, FUV penetrates the I-front and photoionizes the metal
  stages whose thresholds lie below 13.6\,eV (C\,\textsc{i} 11.3, S\,\textsc{i}
  10.4, Si\,\textsc{i} 8.2, Fe\,\textsc{i} 7.9, Mg\,\textsc{i} 7.6\,eV,
  \ldots), producing the PDR-side C\,\textsc{ii} and Mg\,\textsc{ii}.  In the
  FUV band the gas opacity is exactly this low-threshold metal
  photoionization (\code{ion\_metal\_abs}, on by default; H and He do not
  absorb below 13.6\,eV), so the FUV is attenuated by that photoionization
  together with dust --- only where those metals are already ionized does
  dust extinction alone remain.  The metal stage fractions iterate with this
  opacity self-consistently, and the corresponding metal photoheating is in
  the thermal balance (\code{metal\_heat}, on by default); with dust the
  WD01 grain photoelectric heating (\code{grain\_pe}) and the gas--grain
  exchange are on by default, and without H$_2$/CO chemistry PDR-zone
  temperatures are first-order estimates.
\item \textbf{Convergence}: use \code{conv\_crit = 'vol'} for
  production --- the cell-max criterion stalls at the front-cell noise
  floor (and, with \code{add\_fuv}, at no-heating cells where $T_e$
  pins to \code{te\_min}).  Both measures are printed each iteration.
  The explicit diffuse field smooths the front and converges far better.
\item \textbf{Starts}: prefer an ionized initial state; a neutral start
  advances the front $\sim$one cell per iteration.
\item \textbf{kext tables}: the default astrodust and DL07 tables cover the
  EUV directly (astrodust: $1.0\times10^{-4}$--$3.981\times10^4\,\mu$m;
  DL07: $6.2054\times10^{-5}$--$3.981\times10^4\,\mu$m).  If
  \code{ion\_dust\_kext} names an explicit table, that table must cover the
  transported band; tables are sorted on read (the D03 file has an
  out-of-order seam).
\item \textbf{Re-refinement}: one event per run; the old shared-memory
  windows are reclaimed only at exit.
\item \textbf{SEDust}: the grain-model data are resolved from
  \code{sed\_data\_dir} (blank: \code{<executable dir>/SEDust/data}).
  Building the grain model is a startup cost every rank pays (measured
  2026-08-07 at \code{sed\_NT} $=200$: 153~s astrodust, 2.4~s DL07, 0.18~s
  Zubko) whenever the run carries dust; the exact stochastic solve then costs
  $\sim$0.05--0.1~s for each gas leaf (distributed over ranks; not
  re-measured since).
\end{itemize}
